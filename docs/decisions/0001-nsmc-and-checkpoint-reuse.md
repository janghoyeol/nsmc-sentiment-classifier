# 0001. NSMC 선택과 1단계 체크포인트 재사용

## 상태
승인됨 (2026-10-24)

## 배경

`startup-sector-classifier`에서 "토크나이저+트랜스포머를 처음부터 만들고,
사전학습이 실제로 도움이 되는지 랜덤 초기화 베이스라인과 비교해 증명한다"는
패턴을 완성했다(최종 결과: 사전학습 34.9% vs 스크래치 23.4%). 그 다음 작품도
같은 패턴을 재사용하되, 이번에는 더 높은 정확도가 나올 수 있는 과제로
바꿔 보자는 게 출발점이었다.

업종 분류가 낮은 정확도(30%대)에 머문 핵심 원인은 과제 자체의 난이도였다:
- 라벨이 4개뿐으로 줄었다(수집 과정에서 희소 카테고리 제거).
- 위키백과 카테고리 그래프가 DAG라서 한 회사가 여러 업종에 속할 수 있는데,
  단일 라벨만 할당해 정답 자체가 애매한 경우가 있었다.
- 학습 데이터 규모가 작다(수백~수천 단위).

## 결정

**과제를 NSMC(Naver Sentiment Movie Corpus) 이진 감성분류로 바꾼다.**

이유:
- 라벨이 영화 평점에서 자동 추출된 것이라 애매함이 거의 없다(업종 분류의
  "회사가 여러 카테고리에 속함" 문제가 원천적으로 없음).
- 공개 데이터셋으로 이미 train/test가 15만/5만 개로 나뉘어 있어 데이터
  수집 과정의 불확실성(스크래핑 실패, 카테고리 불균형 등)이 없다.
- 이진 분류라 랜덤 베이스라인이 50%로 명확해서, 모델이 뭔가 배웠는지
  판단하기 쉽다.
- `e9t/nsmc` GitHub 레포가 정적 파일로 공개되어 있어 다운로드에 봇 차단·
  속도 제한 문제가 없다(`startup-sector-classifier`의 thevc.kr/위키백과
  API 경험과 대조).

**토크나이저(`JamoTokenizer`)와 모델(`GPT`/`GPTClassifier`) 코드는 그대로
재사용한다.** 자모 단위 토크나이저의 설계 근거(ADR 0002, 이전 프로젝트)가
한국어 텍스트라면 과제와 무관하게 똑같이 적용되고, 모델 구조도 과제
독립적이다 — 바꿀 이유가 없다.

**1단계(사전학습) 체크포인트도 이전 프로젝트에서 그대로 재사용한다.**
위키백과 사전학습(언어모델링)은 다운스트림 과제(업종 분류든 감성분류든)와
무관하게 "한국어 자모 시퀀스의 통계적 구조"를 배우는 과정이라, 매번
4~5시간씩 새로 돌릴 필요가 없다. 이전 프로젝트의 Kaggle 데이터셋에 있는
`pretrain.pt`(1단계 체크포인트, Hugging Face에 올라간 `finetune_pretrained.pt`
와는 다른 파일)와 `vocab.json`을 그대로 가져와 2단계(미세조정)만 새로
돌린다.

트레이드오프: 사전학습 코퍼스가 '업종/회사' 글이 아니라 일반 위키백과
문서라서, 영화 리뷰체(구어체, 줄임말, 비속어 포함)와는 문체 차이가 있다.
이 차이가 전이 효과를 얼마나 줄이는지는 결과로 확인할 사안으로 남긴다 —
필요하면 추후 ADR로 재검토.

## 결과

- `scripts/download_data.py`: NSMC train/test 파일을 받아 jsonl로 변환.
- `scripts/train_finetune.py`: 이전 프로젝트의 핵심 수정사항(차등 학습률
  `--backbone-lr`, 체크포인트에서 shape 결정 필드만 가져오는 설정 로딩)을
  그대로 재사용. NSMC는 이미 train/test가 나뉘어 있으므로 자체 분할 없이
  그대로 쓰고, train 내부에서만 일부를 val로 떼어 epoch별 모니터링에 쓴다
  (최종 성능은 test로만 보고 — 이전 프로젝트는 데이터가 적어 이 구분이
  없었는데, 이번엔 데이터가 충분해 val/test를 분리할 수 있다).
